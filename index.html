Simulation rules

  • CSV rows are processed in timestamp order.
  • BUY opens/adds a long position; SELL reduces/closes a long position. This starter does not simulate shorts, leverage, funding or partial-fill order books.
  • Trade notional is scaled to the configured copy ratio and capped by maximum position size and available virtual cash.
  • Fees are estimated from the configured fee rate. Slippage is not modelled, so results may look better than live execution.
  • Rows older than the selected import window are ignored; duplicate source IDs are skipped when provided.

Settings & data import

Virtual risk settings

The virtual balance is simulated money, not a deposit. Changing the settings resets the paper ledger.

Import trader metrics CSV

Required headings: trader,source,window_start,window_end,roi90_pct,max_drawdown_pct,trades90,active_days90. Optional: roi30_pct,roi7_pct,win_rate_pct,avg_leverage,verified,notes.

For the 90-day research, enter actual observed metrics and the period covered. Do not use a current 30-day ROI as if it were a 90-day return.

Import timestamped trade CSV

Required headings: timestamp,trader,symbol,side,price,quantity. Optional: trade_id. Side must be BUY or SELL. Quantity is the source trader's quantity, not your desired copy size.

A leaderboard is not necessarily a trade feed. Use a permitted export or official API response that actually contains individual trades.

Data quality checklist

  • Confirm the record spans 18 July–18 October 2026, not just the current 30 days.
  • Prefer exchange-linked profiles and official platform data; record the source and when you retrieved it.
  • Use realized returns net of deposits/withdrawals if possible; note ROI formula differences between platforms.
  • Compare drawdown, active days, trade count, leverage and follower profitability; don't rank on ROI alone.
  • Never paste API keys or passwords into this app. This version has no API-key field and no live trading capability.
